# P4 · FACTR 小臂 ↔ Skye 大臂（bridge-less）

目标：小臂 Docker 内 `factr_teleop` 与主机 `skye_robot_driver` 对接，**不**再起 `gento_robot_driver`。

## 对齐点（相对旧 launch 的修正）


| 项         | 旧 `start_teleop_m6_dual.launch.py`                | P4 `start_teleop_m6_dual_gento.launch.py` |
| --------- | ------------------------------------------------- | ----------------------------------------- |
| 指令        | `/left                                            | right_joint_control`                      |
| 反馈        | `/left                                            | right_joint_state`（7 轴分侧）                 |
| Docker 挂载 | `marvin_ws` → `/marvin_ws`，`scripts` → `/scripts` | 同左（含 `bind_leader_arms.py`）               |
| 大臂驱动      | `gento_robot_driver`                              | `skye_robot_driver`                       |


小臂 yaml：`follower_joint_offset` 左=0、右=7，与 14 轴 `/gento/joint_states` 一致。

## ROS Domain（固定 21）

同局域网内若有其他遥操测试机使用 `ROS_DOMAIN_ID=20`，FastDDS 组播会把对方的 `factr_teleop` / Marvin 栈扫进本机 `ros2 node list`（出现重名节点、apex 警告等）。

**本套 P4 链路统一用** `ROS_DOMAIN_ID=21`：vitai 主机、`run_marvin_m6_impedance.sh` 传入 Docker、所有调试终端必须一致。Thor 若参与 ROS 通信，同样设为 21。

换 domain 或重启节点后建议：

```bash
export ROS_DOMAIN_ID=21
ros2 daemon stop; ros2 daemon start
```

干净图期望：`/skye_robot_driver` + `/factr_teleop_left` + `/factr_teleop_right` 各 1 个，无重名警告。

## FastDDS：禁用 SHM（主机 ↔ Docker 必做）

默认 FastDDS = UDP + **共享内存 (SHM)**。本机 `ros2 topic hz` 走 SHM，能看到 ~250 Hz；Docker 即使用 `--net=host --ipc=host`，也经常对不上主机的 SHM locator。

表现：

- 本机：`/gento/joint_states` ~250 Hz
- Docker：`ros2 node list` **没有** `/skye_robot_driver`；`ros2 topic hz /gento/joint_states` 报 `does not appear to be published yet`
- `ros2 topic list` 里仍可能出现 `/gento/joint_states`（FACTR 本地订阅了这个名字），**不代表收到了主机 publisher**
- 此时发 `switch_sync`：小臂订阅为空 → FACTR 进 sync 失败/崩

必须在 **进程启动前** 设置（中途 export 无效），主机和 Docker **两边都要设**，然后重启 driver / factr：

```bash
# 主机
export FASTRTPS_DEFAULT_PROFILES_FILE=/data/coding/tianji/Skye_ROS_Bridge/marvin_ws/fastrtps_no_shm.xml
# Docker 内（marvin_ws 已挂载）
export FASTRTPS_DEFAULT_PROFILES_FILE=/marvin_ws/fastrtps_no_shm.xml
```

该 xml 关闭 builtin 传输（含 SHM），只走 UDPv4。

## 启动顺序



### 1) 主机：大臂驱动

```bash
cd /data/coding/tianji/Skye_ROS_Bridge
export ROS_DOMAIN_ID=21
unset ROS_LOCALHOST_ONLY
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export FASTRTPS_DEFAULT_PROFILES_FILE=/data/coding/tianji/Skye_ROS_Bridge/marvin_ws/fastrtps_no_shm.xml
./scripts/start_skye_for_factr.sh
# 启动日志应含：Gripper enabled ... fb_timeout=1ms
# 另开终端确认（同样 export ROS_DOMAIN_ID=21 与 FASTRTPS xml）：
source skye_ros2_ws/install/setup.bash && export ROS_DOMAIN_ID=21
export FASTRTPS_DEFAULT_PROFILES_FILE=/data/coding/tianji/Skye_ROS_Bridge/marvin_ws/fastrtps_no_shm.xml
ros2 topic hz /gento/joint_states --window 100   # 期望 ~250 Hz（夹爪开启时也应保持）
ros2 service call /gento/set_mode skye_robot_driver/srv/SetMode "{mode: 2}"
```

不要用相对路径 `--params-file install/.../skye_robot.yaml`（在仓库根目录会找不到文件）。日常启动用上面的脚本；若必须 `ros2 run`，params 用绝对路径：

```bash
--params-file /data/coding/tianji/Skye_ROS_Bridge/skye_ros2_ws/install/skye_robot_driver/share/skye_robot_driver/config/skye_robot.yaml
```



### 2) Docker：小臂

```bash
ROS_DOMAIN_ID=21 ./scripts/run_marvin_m6_impedance.sh
```

容器内：

```bash
source /marvin_ws/install/setup.bash
export ROS_DOMAIN_ID=21
export ROS_LOCALHOST_ONLY=0
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export FASTRTPS_DEFAULT_PROFILES_FILE=/marvin_ws/fastrtps_no_shm.xml
ls "$FASTRTPS_DEFAULT_PROFILES_FILE"   # 必须存在；须在 launch 之前 export

# 换臂后先绑定串口（见 docs/新主臂串口绑定.md）
# python3 /scripts/bind_leader_arms.py && source /marvin_ws/.skye/leader_arms.env

# FTDI 低延迟（按实际 ttyUSB；bind 脚本也会写 1）
echo 1 | sudo tee /sys/bus/usb-serial/devices/ttyUSB0/latency_timer
echo 1 | sudo tee /sys/bus/usb-serial/devices/ttyUSB1/latency_timer

# 必须用 gento remap 版 launch（不要用旧 start_teleop_m6_dual.launch.py）
ros2 launch factr_teleop start_teleop_m6_dual_gento.launch.py use_keyboard:=false
# 若 share 未同步，可用绝对路径：
# ros2 launch /marvin_ws/launch_overlay/start_teleop_m6_dual_gento.launch.py use_keyboard:=true
```



### 3) Docker 内确认能收到大臂（进 sync 前必做）

另开 Docker 终端或同一容器（同样 export 上面 4 个变量）：

```bash
ros2 node list
# 必须同时有：/skye_robot_driver  /factr_teleop_left  /factr_teleop_right

ros2 topic hz /gento/joint_states --window 20
# 期望 ~250 Hz。若报 does not appear to be published yet：xml 没生效，两边重启并检查 FASTRTPS_DEFAULT_PROFILES_FILE
```



### 4) 模式联调

FACTR 已 IDLE、Docker 内 joint_states 已有频率后再切。托住双小臂。

```bash
export ROS_DOMAIN_ID=21
ros2 topic pub --once /mode/switch_stop  std_msgs/msg/String "{data: switch_stop}"
sleep 1
ros2 topic pub --once /mode/switch_sync  std_msgs/msg/String "{data: switch_sync}"
# 托住小臂，等 SYNCED（可能数秒～十几秒）
ros2 topic echo /teleop/state --once \
  --qos-durability transient_local --qos-reliability reliable
# 看到 SYNCED 后再：
ros2 topic pub --once /mode/switch_teleop std_msgs/msg/String "{data: switch_teleop}"
```

## 夹爪测试流程



### 1. 确认夹爪相关 Topic 是否存在

```bash
export ROS_DOMAIN_ID=21
ros2 topic list | grep gripper
ros2 topic info -v /left_gripper/state
ros2 topic info -v /left_teleop_gripper/ctrl
# 期望：/left_gripper/state 的 Publisher 是 skye_robot_driver
```



### 2. 频率验证

```bash
ros2 topic hz /left_gripper/state --window 50
ros2 topic hz /right_gripper/state --window 50
# 期望频率：约 100 Hz（由 gripper_rate_hz 决定）
# 同时确认关节反馈未被夹爪拖慢：
ros2 topic hz /gento/joint_states --window 100   # 仍应 ~250 Hz
```



### 3. 查看夹爪位置状态

```bash
ros2 topic echo --once /left_gripper/state
```



### 4. 位置控制测试

默认 `gripper_invert: true`（FACTR 扳机：松开=1/开，按下=0/闭；电机仍是 0=开 1=闭）。

```bash
# 夹爪0开，1闭合。   FACTR 扳机开1，暗下去0  需要改映射
ros2 topic pub --once /left_teleop_gripper/ctrl sensor_msgs/msg/JointState \
  "{name: ['gripper_joint'], position: [1.0]}"   # 开
ros2 topic pub --once /left_teleop_gripper/ctrl sensor_msgs/msg/JointState \
  "{name: ['gripper_joint'], position: [0.0]}"   # 闭
```

纯电机测试（不经过 FACTR 语义）把 `gripper_invert` 设 `false` 后：`0.0`=开，`1.0`=闭。

左：ARM0 + ID1；右：ARM1 + ID2。右爪硬件问题另跟。

### 5. 关节 signs（已按实机修正）

现场确认左右臂 **j4 / j6 / j7** 与机械臂反向，原表这三轴为 `-1`。已改为全 `+1`：

```text
left/right_joint_signs = [1, 1, 1, 1, 1, 1, 1]
#                         j1 j2 j3 j4 j5 j6 j7
```

指令：`mapped = leader * signs`；现与 `/gento/joint_states`（SDK 原值）同一坐标系，sync 后进 TELEOP 这三轴不应再跳符号。

**复测（TELEOP，托住，一次一轴）：** 正转小臂 j4/j6/j7，大臂同轴应同向。若仍反，把对应轴改回 `-1` 并重启 driver。



## 不要做

- 主机与 Docker 使用不同的 `ROS_DOMAIN_ID`（会互相看不见）
- 漏设 `FASTRTPS_DEFAULT_PROFILES_FILE`（本机有 250Hz、Docker 看不到 `/skye_robot_driver`，sync 空订阅）
- 只在一边设 xml，或进程起来之后才 export（必须两边、启动前）
- 与同 LAN 其他测试机共用 domain 20（会扫进对方节点，出现两套 `factr_teleop_*`）
- 同时启动 `gento_robot_driver` 与 `skye_robot_driver`
- 使用未 remap 的 `start_teleop_m6_dual.launch.py`（会订错反馈 topic）
- 把 `scripts/` 挂成 `/marvin_ws`（旧 bug，已修）
