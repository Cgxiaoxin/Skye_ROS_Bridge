## 0. 架构速记

```text
FACTR(小臂,闭源 .so,500Hz)                        skye_robot_driver(大臂,C++,250Hz)
  读小臂 dynamixel + grav_comp →                      订 /gento/{left,right}_joint_control
  /gento/{left,right}_joint_control (7pos)     →      relative 映射 → clamp → limit_delta → SDK
  sync(按1): 小臂位置控制(Ruckig)去跟大臂绝对位姿      发布 /gento/joint_states(14) → FACTR sync 用
  teleop(按2): 小臂自由态, 发布指令
```

- 映射公式(相对):`q_cmd[i] = gento_ref[i] + sign[i]*(q_leader[i] − q_leader_ref[i])`,order=identity,signs 全 +1。
- 进入 teleop 时(收到首帧):`leader_ref`=当前小臂角,`gento_ref`=当前大臂反馈角 → 零跳变进入。
- **sync 用独立重力前馈**:`hold_ruckig_control.ruckig_gravity_comp_gain=[0.15,0.15,0.15,0.35,0.3,0.3,0.3]`(J4 已调),不是主 `gravity_comp.gain`。

## 2. 问题清单与根因

### P1. 启动初始姿态 / "抬的太高"
- 初始位姿**确定非随机**:上电前对齐蓝线/红标 = 物理 home;FACTR 接管后 Idle 态控制力全是确定性的。
- 项目 gravity gain == 厂商(J1=0.25),不是偏离厂商导致;可能原因:
  ① 该参数在本台臂上过补偿(J5/J7=1.0 全补偿);② null_space 曾开启拉向 target(现已关);③ 更早观察时可能是 J1=0.6 旧版。
- **J1 gain 与"抬多高"无关**:J1 是基座铅垂偏航轴,重力矩≈0,其 gain 影响偏航漂移而非竖直位置。
- 控制手段:null_space 关闭/改 target、J2/J3/J5 gain 现场微调、启动不急着 sync。

### P2. J1 角度回绕 → 大臂猛转
- 现象:用力把小臂 J1 转过 180° 后,大臂 J1 猛甩到对侧硬限位(近一圈)。
- 根因:角度表示不连续(单圈约定),FACTR 输出越 ±π 时报告值跳 2π(如 +3.1→−3.1);`delta=q_now−q_ref` 突变 ~2π → 大臂目标 clamp 到负限位 → 猛甩。
- 触发条件:FACTR 限位势垒 ±3.0 rad < π,正常到不了,但势垒是软力矩、可被顶过。
- 结论:很可能是之前大臂突然猛转的直接原因。
- 方案:driver relative 映射加**最短路径 unwrap** `delta=atan2(sin,cos)` 规整到 (−π,π]。

### P3. 大臂跟不上 / 绝对位姿
- 目标:大臂跟上小臂 + 不丢绝对位置 + 不动小臂侧(避免影响手感);采集动作慢。
- 关键认知:
  - relative 映射 target 是绝对增量(`gento_ref+delta`),停手即追平 → **不会永久累积误差**;
  - 落后主因是大臂 SDK `velocity_ratio`(现 30)与动力学,`max_delta_per_cycle=0.05` 非瓶颈;
  - 慢速 + 无回绕 + 无限位饱和时,relative 天然保持大臂↔小臂绝对位姿对应。
- sync 深挖见 §3。

### P4. 符号错误即镜像
- 已真机验证全 +1 正确;换臂/换 URDF 需复测。不处理。

### P5. max_delta_per_cycle 语义
- driver 层每帧指令限速 `|cmd−cmd_prev| ≤ 0.05 rad/关节`,逐轴独立;非 SDK 物理限速。
- 超限不失效/不丢位置:该帧最多走 0.05,目标照常更新,慢下来即追平。
- 作用:防单帧跳变(spike/回绕/进入首帧)瞬间甩动。500Hz 下=25 rad/s,慢速采集不触发。

### P6. torque_feedback(FACTR 小臂侧)
- 大臂→小臂力反馈:用大臂模型估计 `τ_ext=τ_total−τ_gravity`,按 motor_scalar/gain 缩放加到小臂。
- 现状 enable False;遥操暂不需要,不紧急。

## 3. sync 深挖

### 3.1 sync 是什么
按 1 → FACTR 读 `/gento/joint_states`(大臂 14 轴),用 **Ruckig 位置控制**把小臂驱动到大臂的绝对位姿(小臂为被控对象)。期间操作者"托住"小臂。

### 3.2 sync 需要重力/摩擦补偿吗?
- **sync 用 `ruckig_gravity_comp_gain`(15%~35%,低),不是主 gravity gain**。
- 位置控制器靠 `kp×误差 − kd×速度` 就能克服重力"抬起来、大致到位" → **不加补偿也能走**;
- 但无重力前馈会有**稳态下垂**(平衡时 `误差≈τ_g/kp`),肩/肘大负载关节尤其明显;无摩擦补偿会有 stiction 残余误差。
- 结论:**sync 不要关补偿**(影响到位精度),但它不是 sync 走不动的根因;真有问题先查 `ruckig_kp`/`joint_position_control.kp` 与可达性。
- 当前已增强 J4 sync 参数(ruckig_kp 0.38、gc_gain 0.35),应是针对"J4 到位弱"的现场调优。

### 3.3 为什么"重新切回 sync"会位置对不上
sync 是**绝对位姿对齐**(数值一致),依赖四个前提,任一不满足即数值对齐≠物理对齐:
1. **无回绕**:teleop 期间小臂某关节越 ±π 后物理在多圈位,sync 按单圈数值命令 → 差 2π;
2. **可达性**:大臂位姿在小臂限位势垒外,或手挡着 → 小臂顶势垒,报 SYNCED 但实际没到;
3. **工作空间**:大臂跑到了小臂构型复现不了的位置;
4. **符号/零点链一致**:sync 路径与 teleop 映射路径需同一套 sign/offset(两 URDF 轴向有差异,靠现场标定兜底)。

### 3.4 为什么断电重启"就好了"
断电清掉小臂舵机多圈计数与 FACTR 内部状态,强制从物理零点重新初始 sync——本质是"从零重新标定"。

### 3.5 设计层面
当前有**两套互不相干的对齐机制**:FACTR sync(小臂去匹配大臂,依赖小臂可达/无回绕)与 driver 相对映射(进入时捕获 refs)。重新对齐只能靠前者,而前者脆弱。
