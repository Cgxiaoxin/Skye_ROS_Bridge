# 问题追踪:右小臂 J4 对不齐(2026-08-26)

> 状态:**进行中**。已排除零点漂移、driver 代码、僵尸进程;怀疑重力补偿/URDF 模型/符号链。本文档用于跨窗口/跨会话延续上下文。

## 一、现象

- 右小臂与右大臂**绝对位姿对不上**(J4 最明显),左臂正常;
- sync 后小臂松手,肘(J3)/腕(J4)下垂:J3=+37.4°、J4=-38.4°;
- 调大右臂 `gravity_comp.gain` J3/J4 → 1.0 后**稍好,但 J4 仍对不齐**。

## 二、已确认的事实(2026-08-26 现场数据)

| 项 | 结论 |
|---|---|
| 零点漂移 | **排除**。小臂摆到标记位读数 ≈0(J3=-1.5°, J4=-1.9°),零点正确 |
| sync 后下垂 | 真实物理下垂(重力气动力平衡点),非读数错误 |
| 下垂方向 | J3=+37°、J4=-38°,方向与当前 `joint_signs`(J3=+1, J4=-1)一致 → **符号不是主因** |
| driver 健康 | 指令↔大臂误差 ≤6°;J1/J3/J5 连续 unwrap 已合入 main(2398c8a) |

| 僵尸进程 | 已清理(65× control_arbiter + 39× episode_recorder),见 docs/log.md |
| sync 状态 | FACTR 报 `SYNCED`,但小臂实际未贴住大臂位姿 |

## 三、关键机制(为什么"对不上")

1. relative 映射 `q_cmd = gento_ref + delta` **只跟踪增量**,进入 teleop 时的绝对偏差被永久保留;
2. sync 结束后小臂松手 → 下垂到 J3=+37°/J4=-38°;大臂在目标位(≈0°);
3. 按 2 进 teleop → 该偏差被当基准捕获 → 右臂看起来持续对不上;
4. 调高 J3/J4 gain 只减小下垂幅度,若 J4 仍偏,说明**残留补偿误差**或**模型/符号链问题**。

## 四、未决问题

1. **J4 gain=1.0 仍对不齐的原因**:
   - a. URDF(`m6right_isomorphism.urdf`)与实际右小臂几何不匹配 → 重力补偿模型力矩有误;
   - b. J4 `joint_signs=-1` 与重力模型方向的残余误差(方向大体对,但幅度/零点不完全对);
   - c. sync 目标本身与大臂 J4 的映射/符号链问题。
2. sync 到底把小臂 J4 驱动到了哪个值?需要抓 sync 全程数据。

## 五、下一步验证(按优先级)

1. **抓 sync 全程 250Hz**:小臂 J4 / 大臂 J4 / 指令 J4 三路对比,看 sync 目标与真实跟随、下垂发生在哪一刻;
2. **试 J4 符号反转**:右臂 `dynamixel.joint_signs[3]`(J4)临时 -1→+1,看下垂方向是否反转 → 判别符号;
3. **核对 URDF**:比对 `m6right_isomorphism.urdf` 的 J4 origin/轴 与物理舵机实际方向/零点;
4. 若模型不匹配 → 校正 URDF 或接受该偏差(或 sync 时人为托住小臂)。
