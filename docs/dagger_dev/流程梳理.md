# HITL DAgger 流程梳理（现场笔记）

> 配套：[`unijepa_dagger_实机验证流程.md`](unijepa_dagger_实机验证流程.md)、[`hitl_dagger_thor_现场联调步骤.md`](hitl_dagger_thor_现场联调步骤.md)

## 1. 核心结论

- `/skye/policy_action` **不直接进 driver**，只进 **control_arbiter**。
- 真正写大臂的只有 arbiter：
  - **策略 / 回零**：`/gento/{left,right}_joint_control_abs`（绝对关节）
  - **遥操**：`/gento/{left,right}_joint_control`（相对关节）
- `/gento/joint_states` 是 **driver 反馈**（约 250Hz），不是控制入口。
- 没有 `gento_control_state` 这种「收控制」topic。

测「策略能不能控臂」=：

```text
/skye/policy_action
  → arbiter(AUTONOMOUS)
  → /gento/*_joint_control_abs
  → skye_robot_driver 存活
  → 真机
```

## 2. 数据流

```text
                    ┌─────────────────┐
   图 + 关节反馈    │ 5090 UniJEPA     │  ZMQ tcp://192.168.201.253:5569
                    │ （仅策略闭环）    │
                    └────────┬────────┘
                             │ action [L7,R7,Lg,Rg] 绝对弧度
                             ▼
┌─ DAgger client / dummy ─┐      ┌──────── arbiter ────────┐
│ pub → /skye/policy_action│─────►│ 唯一允许写 /gento/*     │
└─────────────────────────┘      │                         │
小臂 teleop                       │ AUTONOMOUS → *_abs      │
 /skye/teleop_action_*  ─────────►│ HUMAN      → *_control  │
 /skye/intervention_cmd           │ HANDOVER_* → 不写臂     │
                                  └────────────┬────────────┘
                                               ▼
                                    skye_robot_driver
                                               │ UDP
                                               ▼
                                          6.6.7.191
                                               │
                                               ▼
                                    /gento/joint_states（反馈）
```

| Topic | 角色 | 谁写 → 谁读 |
|-------|------|-------------|
| `/skye/policy_action` | 口 A：`PolicyActionChunk`（`chunk_size=16`，绝对弧度） | client / dummy → arbiter |
| `/skye/control_mode` | 模式广播 | arbiter → 所有人 |
| `/gento/*_joint_control_abs` | 绝对指令（策略） | **仅 arbiter** → driver |
| `/gento/*_joint_control` | 相对指令（遥操） | **仅 arbiter** → driver |
| `/gento/joint_states` | 大臂反馈 | driver → arbiter / client / dummy |
| `/skye/teleop_action_*` | 小臂目标 | teleop → arbiter |

模式：

| 模式 | 行为 |
|------|------|
| `AUTONOMOUS` | 吃 `/skye/policy_action` → 写 `*_abs` |
| `HUMAN` | 转发 teleop → 写 `*_control` |
| `HANDOVER_SYNC` | 不写臂，等同步 |

## 4. 现阶段测试结论（dummy 口 A）

**这是正常的。**

| 检查项 | 你的结果 | 含义 |
|--------|----------|------|
| 收到 `joint_states` 后开始 publish | ✅ | driver 反馈通 |

## 5. 现阶段推荐整流程（按序）

### C0 — 底座存活（每次开跑先做）

| 序 | 机器 | 命令 | 验收 |
|----|------|------|------|
| 1 | PC | `./scripts/start_skye_for_factr.sh thor` | 不崩；`ros2 topic hz /gento/joint_states` ≈250 |
| 2 | PC | `ros2 launch skye_factr_teleop start_teleop_m6_dual_hitl.launch.py robot_profile:=thor` | 左右 IDLE |
| 3 | PC | `ros2 launch skye_hitl_dagger hitl_dagger.launch.py robot_profile:=thor` | `/skye/control_mode` = AUTONOMOUS |
| 4 | Thor | `cd docs/dagger_dev/client_thor && bash ensure_cameras.sh` | 三路相机有图 |

禁止：Thor / PC **同时**起两路 driver。

### C1 — 口 A（假策略，不启 5090 / client）

```bash
# 任一已 source + Domain=20 的终端
ros2 run skye_hitl_dagger pub_dummy_policy_chunk

# 另窗
ros2 topic echo /skye/policy_action --once
ros2 topic hz /gento/left_joint_control_abs
```

期望：`policy_action` 有消息；`*_abs` 有 hz。臂可几乎不动（hold）。

### C2 — HITL 接管（可选，仍可不启 5090）

```bash
ros2 topic pub --once /skye/intervention_cmd std_msgs/msg/String "{data: 'takeover'}"
# 两侧 SYNCED 后
ros2 topic pub --once /skye/intervention_cmd std_msgs/msg/String "{data: 'enter_teleop'}"
# 轻动小臂 → 大臂跟随
ros2 topic pub --once /skye/intervention_cmd std_msgs/msg/String "{data: 'return'}"
# 回到 AUTONOMOUS 后再测策略
```

### C3 — UniJEPA 闭环（dummy 先停掉）

| 序 | 机器 | 命令 | 验收 |
|----|------|------|------|
| 5 | 5090 | `./serve_unijepa_dagger.sh` | listening `:5569` |
| 6 | Thor（或 PC，有相机） | `cd docs/dagger_dev/client_thor && ./run_client_dagger.sh` | 先 slow-home；成功后才有 5090 推理 |

注意：

- **slow-home 不打 5090**（本地轨迹 → `/skye/policy_action`）。
- 服务器无推理日志 = 还在回零 / 回零失败，不代表协议错。
- 成功标志：`DAGGER slow-home settled` → 随后 `DAGGER published PolicyActionChunk` / `Received chunk`；5090 开始有请求。

临时跳过回零（仅调试，臂需已在安全位）：

```bash
DAGGER_SLOW_HOME=0 ./run_client_dagger.sh
```

### 收工顺序

```text
停 client / dummy → return（若在遥操）→ 停 arbiter → 停 teleop → 停 driver → 停 5090
```

## 6. 常见误判

| 现象 | 真实原因 |
|------|----------|
| dummy「卡住」在 Waiting joint_states | driver 已死 / Domain 不通 |
| echo `/skye/policy_action` 为空 | 没有 publisher（dummy/client 未起） |
| dummy 有数据但臂不动 | hold 当前姿 = 正常；再查 `*_abs` hz + AUTONOMOUS |
| 5090 无推理 | 还在 slow-home，或 client 未过回零 |
| Thor driver `-11` | SDK/进程崩溃；用 PC driver workaround，且勿双开 |

## 8. 抖动 / 撞墙根因与修复（对照旧 `run_robot_unijepa`）

### 根因（已定位）

旧链路在 **写 Gento 前**做 quintic 回零 + ActionQueue 融合 + direct_guard。  
早期 DAgger 把 **服务器 raw chunk** 直灌 `/skye/policy_action`，护栏只进 `command_preview`，导致抖/易撞墙。

### 修复后的职责划分（当前代码）

```text
【client / vendor】平滑在 publish /skye/policy_action 之前
  回零：dagger_quintic + dagger_home（0.5deg @ 20Hz + max_lead）
  推理：merge(ActionQueue) → guard/setpoint slew → hold chunk pub

【arbiter】只选源（AUTONOMOUS / HUMAN），写 /gento/*
  保留 step0 jump rebase 作安全网；不重写 weighted_average

【5090 / driver】不变
```

| 阶段 | 模块 | 行为 |
|------|------|------|
| 回零 | `dagger_home.py` / `dagger_quintic.py` | 与 legacy 同语义 quintic；经口 A 发 abs rad |
| 推理 | `async_robot_client.py` | **不再** raw pub；融合+护栏后的 command → hold×16 |
| 默认 | `run_robot_dagger.sh` | `DAGGER_HOME_STEP_DEG=0.5` `HZ=20` `LEAD=5` |

现场复测期望：

1. 日志出现 `DAGGER quintic-home` / `DAGGER published smoothed PolicyActionChunk`
2. 回零连续，无「16 步一顿」
3. 相邻发布目标跳变远小于此前 ~45°
4. 仍仅 arbiter 写 `/gento/*_abs`
