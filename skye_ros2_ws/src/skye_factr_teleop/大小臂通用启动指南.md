# 大小臂启动指南

各终端从仓库根目录执行命令，项目路径均相对于仓库根目录。

## 第一部分：统一启动流程

默认 Orin 大臂、小臂 B、双侧，左右串口按 USB 唯一标识自动识别。设备差异按第二部分调整。

### 1. 首次设置与编译（终端Pre）

指定大臂设备（thor/orin），并编译。

```bash
bash scripts/teleop.sh configure orin
bash scripts/teleop.sh build
```

### 2. 启动前检查-启动大小臂（终端A）

检查 ROS 编译安装环境； 检查指定大臂（thor/orin）的网络、重复驱动； 检查指定小臂（a/b）的 USB、配置、串口权限与占用，设置 FTDI 延迟为 1 ms。

```bash
bash scripts/teleop.sh check --robot orin --device b --fix-latency
```

大臂进入IMP模式； 小臂进入IDLE模式。

```bash
bash scripts/teleop.sh start --robot orin --device b
```

### 3. 同步-遥操-停止（终端B）

加载环境。

```bash
source skye_ros2_ws/scripts/setup_factr_teleop_env.sh --robot orin --device b
```

进入sync阶段。

```bash
ros2 topic pub --once /mode/switch_sync std_msgs/msg/String '{data: switch_sync}'
```

在终端 A（运行 `teleop.sh start` 的终端）观察带 `[left]` / `[right]` 的同步日志：

- 状态变化立即输出：`TELEOP_SYNCING`（轨迹运动）→ `HOLD_SETTLING`（到位稳定检查）→ `SYNCED`（同步成功）。
- 同步期间每秒输出当前达标轴数，以及未达标关节的位置误差、速度与配置阈值的比较；包含 J1–J7 和夹爪 `gripper(ID8)`，位置误差相对本次同步的最终目标计算。
- `Continuous settling` 显示持续达标时间 / 要求时间。八轴必须同时满足位置和速度阈值，并连续保持配置的 `settle_duration`，才算同步成功。
- 超时输出 `sync_timeout`（轨迹超时）或 `settle_timeout`（到位稳定超时）及失败时的关节误差。

**分别确认各侧输出 `SYNCED：同步成功`**，再进入遥操；任一侧失败时共同 stop。单侧启动时仅确认所选侧。

进入teleop阶段。

```bash
ros2 topic pub --once /mode/switch_teleop std_msgs/msg/String '{data: switch_teleop}'
```

托稳小臂，执行 stop。

```bash
ros2 topic pub --once /mode/switch_stop std_msgs/msg/String '{data: switch_stop}'
```

## 第二部分：各种设备条件的个性化修改方案

### 1. 大臂与小臂选择

大臂和小臂独立选择，可交叉连接。

| 目标大臂 | 保存设置 | 控制器 IP | 默认 domain |
|---|---|---|---|
| Thor | `bash scripts/teleop.sh configure thor` | `6.6.7.191` | `20` |
| Orin | `bash scripts/teleop.sh configure orin` | `6.6.7.190` | `21` |

| 小臂 | 左 USB 序列号 | 右 USB 序列号 | 配置目录（相对 `skye_factr_teleop/`） |
|---|---|---|---|
| A | `FTBEO9L1` | `FTBEO8WL` | `config/` |
| B | `FTB8HNOT` | `FTAO51EA` | `config/orin/` |

主流程用 `--device b` 选择小臂 B，左右串口仍自动识别；换用 A 时改为 `--device a`。

### 2. 临时启动选项

| 条件 | 添加选项 |
|---|---|
| 临时控制另一套大臂 | `--robot thor` 或 `--robot orin` |
| 指定小臂 A / B | `--device a` 或 `--device b` |
| 只接左 / 右小臂 | `--side left` 或 `--side right`；仍启动双侧大臂驱动 |
| 指定 domain | `--domain 20`（按现场设置） |

`check`、`start` 和各终端环境脚本使用相同选项。例如 Thor + B + 左侧 + domain 20：

```bash
# 终端 A：仓库根目录
bash scripts/teleop.sh check --robot thor --device b --side left --domain 20 --fix-latency
bash scripts/teleop.sh start --robot thor --device b --side left --domain 20
```

```bash
# 终端 B / 记录终端：各自从仓库根目录加载
source skye_ros2_ws/scripts/setup_factr_teleop_env.sh --robot thor --device b --side left --domain 20
```

默认 domain 为 Thor=20、Orin=21。单侧模式仅检查所选侧电机。

### 3. 硬件差异的修改位置

小臂 YAML 指对应配置目录中的 `grav_comp_m6_left.yaml` / `grav_comp_m6_right.yaml`；大臂 profile 指 `skye_robot_driver/config/profiles/thor.yaml` / `orin.yaml`。

| 设备条件 | 修改方案 |
|---|---|
| 更换 USB 转换器 | 用 `ls -l /dev/serial/by-id/` 查看标识，更新对应小臂 YAML 的 `dynamixel.dynamixel_port`，核对实体左右侧 |
| 小臂零点、方向不同 | 修改对应小臂 YAML 的 `dynamixel.joint_offsets`、`joint_signs` |
| 小臂舵机、电流或同步参数不同 | 核对 `dynamixel.servo_types`、`baudrate`、`current_limit_ma`|
| 大臂方向不同 | 修改对应大臂 profile 的 `left_joint_signs`、`right_joint_signs` |
| 大臂夹爪不同 | 修改对应大臂 profile 的夹爪类型、接线与行程参数 |
| 控制器 IP 改变 | 同时更新 `scripts/teleop.py` 的 ping 目标和对应大臂 profile 的 `robot_ip` |
| 换主机架构 | 准备 `third_party/gento_sdk/lib/<x86_64或aarch64>/libGentoSDK.so`，在目标主机重新编译 |

修改大臂 profile 后须重新 `build`；修改小臂源 YAML 后重启并复查。

### 4. 检查失败处理

| 提示 | 处理 |
|---|---|
| 串口权限不足 | 核对 `dialout` 组，添加用户后重新登录 |
| 串口占用 | 正常退出旧驱动、Docker 或串口工具 |
| FTDI 延迟异常 | 执行 `check --fix-latency` |
| USB 匹配失败 | 核对接线、唯一标识、`--device` 和 `--side` |
| 控制器不通 | 核对目标大臂、供电、主机网口地址及路由 |
