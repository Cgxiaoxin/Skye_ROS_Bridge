# 同步阶段通用调参指南

默认 **Orin + 小臂 B + 右侧 + domain 21**，一次调一侧。设备差异见第三部分。

各终端从项目根目录执行，项目路径均相对于根目录；`/opt`、`/dev`、`/sys` 为系统路径。

## 第一部分：无大臂统一调参流程

### 1. 首次或更新代码后编译

```bash
cd skye_ros2_ws
source /opt/ros/humble/setup.bash
export PATH="/usr/bin:$PATH"
colcon build --packages-select skye_factr_description skye_factr_teleop --symlink-install
```

### 2. 公共环境：每个终端执行

```bash
source skye_ros2_ws/scripts/setup_factr_teleop_env.sh --robot orin --device b --side right --domain 21
cd .. # 环境脚本进入工作空间，此处返回项目根目录
SIDE=right CONFIG="$RIGHT_CONFIG"
```

A 启动小臂，B 记录，C 发运动请求，D 专门停止。所有终端使用同一配置和 domain。

### 3. 检查、改参、启动（终端 A）

退出旧驱动，核对串口与配置；串口须有读写权限、无占用。

```bash
ls -l /dev/serial/by-id/
rg -n 'dynamixel_port:' "$CONFIG"
USB_BY_ID=/dev/serial/by-id/usb-FTDI_USB__-__Serial_Converter_FTAO51EA-if00-port0
TTY_PATH=$(readlink -f "$USB_BY_ID")
fuser "$TTY_PATH"
```

FTDI 延迟设为 1 ms 并回读：

```bash
if test -c "$TTY_PATH"; then
  TTY_NAME=$(basename "$TTY_PATH")
  echo 1 | sudo tee "/sys/bus/usb-serial/devices/${TTY_NAME}/latency_timer"
  cat "/sys/bus/usb-serial/devices/${TTY_NAME}/latency_timer"
else
  echo "串口不存在，请先检查连接"
fi
```

停止节点后修改 `$CONFIG`，再启动；每次改参均须重启。

```bash
ros2 launch skye_factr_teleop "start_teleop_m6_${SIDE}.launch.py" \
  robot_profile:=orin "${SIDE}_config:=$CONFIG" sync_diagnostics:=true
```

### 4. 每轮先记录（终端 B）

```bash
mkdir -p skye_ros2_ws/log/sync_trials
OUTPUT="skye_ros2_ws/log/sync_trials/${SIDE}_sync_$(date +%Y%m%d_%H%M%S).json"
echo "$OUTPUT"
ros2 run skye_factr_teleop skye_factr_sync_trial record \
  --side "$SIDE" --config "$CONFIG" \
  --output "$OUTPUT" --duration 180
```

等待 `Recording ...; awaiting move, then IDLE`。**记录器退出不会停止小臂。**

### 5. 预览、执行（终端 C）

在 `IDLE` 下预览七轴归零目标，确认实体路径无干涉后执行：

```bash
ros2 run skye_factr_teleop skye_factr_sync_trial move \
  --side "$SIDE" --config "$CONFIG" --target 0 0 0 0 0 0 0
```

```bash
ros2 run skye_factr_teleop skye_factr_sync_trial move \
  --side "$SIDE" --config "$CONFIG" --target 0 0 0 0 0 0 0 --execute
```

七个数对应 J1～J7，单位 rad；夹爪使用 YAML 的 `gripper_setpoint`。单轴小步试验可将 `--target ...` 换成 `--joint-id 1 --delta 0.05`。

观察 `TELEOP_SYNCING → HOLD_SETTLING → SYNCED`。八轴位置、速度须同时达标并持续 `settle_duration`。成功后观察保持；抖动、干涉或报警时立即停止。

### 6. 停止、保存、失能回读

终端 D：托稳小臂并停止。

```bash
ros2 topic pub --once /mode/switch_stop std_msgs/msg/String '{data: switch_stop}'
```

确认 `IDLE`、B 保存记录后，在 A 按 Ctrl+C 退出驱动。保持供电、待串口释放，在原终端 B 回读：

```bash
ros2 run skye_factr_teleop skye_factr_dynamixel_readonly_check -- \
  --side "$SIDE" --config "$CONFIG" --frames 2 --interval 0 \
  --output "${OUTPUT%.json}_torque_disable.json"
```

核对 `automated_result=PASS`、ID1～8 `torque_enabled=false`。

### 7. 下一轮

定位未达标轴 → 每轮只改一个轴的一类参数 → 重启 → 重新记录、复测。尽量固定起点、目标和负载，保留改动前后值及结果。

## 第二部分：有大臂统一调参流程

### 1. 编译、检查

```bash
bash scripts/teleop.sh configure orin
bash scripts/teleop.sh build
bash scripts/teleop.sh check --robot orin --device b --side right --domain 21 --fix-latency
```

### 2. 加载环境、启动

A～D 和新增的 E 均执行第一部分第 2 节公共环境。E 启动大臂，确认 IMP 模式就绪：

```bash
ros2 launch skye_robot_driver skye_robot_driver.launch.py robot_profile:=orin
```

A 按第一部分第 3 节启动小臂。已有大臂驱动时沿用；不要同时运行 `teleop.sh start`。大臂驱动仍启动双侧。

### 3. 检查反馈、记录、同步

C 检查本侧反馈，确认七轴角度、方向和目标可达，大臂保持静止：

```bash
ros2 topic echo --once "/gento/${SIDE}_joint_states" sensor_msgs/msg/JointState
```

B 按第一部分第 4 节开始新记录。记录就绪且小臂为 `IDLE` 后，C 执行：

```bash
ros2 topic pub --once /mode/switch_sync std_msgs/msg/String '{data: switch_sync}'
```

本轮目标截取自大臂七轴反馈，夹爪仍用配置目标；同步和保持期间须持续有效反馈。此流程不执行 `move --execute`。

### 4. 观察、停止、复测

确认 `SYNCED` 并观察保持，再按第一部分第 6～7 节停止、回读和改参。换目标前先 stop 回到 `IDLE`。全部结束后退出 E 的大臂驱动。

双侧运行时分别确认左右 `SYNCED`；任一侧失败时共同 stop。模式话题会作用于同 domain 内所有订阅的小臂。

## 第三部分：各种设备条件的个性化修改

### 1. 设备选择

大臂、小臂可独立搭配；各终端选项保持一致。

| 条件 | 修改 |
|---|---|
| Thor 大臂 | `configure thor`、`--robot thor`、`robot_profile:=thor`；默认 domain 20，IP `6.6.7.191` |
| Orin 大臂 | `configure orin`、`--robot orin`、`robot_profile:=orin`；默认 domain 21，IP `6.6.7.190` |
| 小臂 A | `--device a`；配置在 `skye_ros2_ws/src/skye_factr_teleop/config/` |
| 小臂 B | `--device b`；配置在 `skye_ros2_ws/src/skye_factr_teleop/config/orin/` |
| 左侧 | `--side left`，并设 `SIDE=left CONFIG="$LEFT_CONFIG"` |
| 右侧 | `--side right`，并设 `SIDE=right CONFIG="$RIGHT_CONFIG"` |
| 自定义 domain | 所有终端统一 `--domain N` |
| 独立试验配置 | 每个终端设 `CONFIG="$PWD/<相对项目根目录的 YAML 路径>"` |

小臂配置文件为对应目录的 `grav_comp_m6_left.yaml` / `grav_comp_m6_right.yaml`。

| 小臂 | 左 USB 序列号 | 右 USB 序列号 |
|---|---|---|
| A | `FTBEO9L1` | `FTBEO8WL` |
| B | `FTB8HNOT` | `FTAO51EA` |

换设备时同步修改手动检查的 `USB_BY_ID`，以 `/dev/serial/by-id/` 和 YAML 为准。

### 2. 硬件差异

| 条件 | 修改位置 |
|---|---|
| USB、零点、方向 | 小臂 YAML：`dynamixel.dynamixel_port`、`joint_offsets`、`joint_signs` |
| 舵机、电流、波特率 | 小臂 YAML：`dynamixel.servo_types`、`current_limit_ma`、`baudrate` |
| 大臂方向、夹爪 | `skye_ros2_ws/src/skye_robot_driver/config/profiles/thor.yaml` / `orin.yaml` |
| 控制器 IP | 同时改 `scripts/teleop.py` ping 目标和大臂 profile 的 `robot_ip` |
| 主机架构 | 准备对应架构 `libGentoSDK.so`，重新编译 |

小臂 YAML 改后重启节点；大臂 profile 改后重新 build。

### 3. 核心调参位置

以下简写 `ruckig`、`hold` 均位于小臂 YAML 的 `controller.sync_hold_control`。

| 问题 / 目标 | 参数与检查 |
|---|---|
| 轨迹跟踪、抖动 | `ruckig.kp/kd`；先检查反馈、周期和电流限幅 |
| 参考轨迹过快 | `ruckig.max_velocity/max_acceleration/max_jerk` |
| 保持静差 | `hold.kp/ki/i_max/i_thresh`；同时检查重力、摩擦与电流限幅 |
| 保持抖动 | `hold.kd`；增大 Kd 不一定更稳定 |
| 重力补偿 | `ruckig.gravity_comp_gain`、`hold.gravity_comp_gain` |
| 到位判定 | `hold.sync_position_tolerance/sync_velocity_tolerance/settle_duration` |
| 超时 | `ruckig.trajectory_timeout`、`hold.settle_timeout`；先定位未达标原因 |
| 目标靠近限位 | 核对 `controller.limit_barrier_control`，先检查目标和标定 |
| 夹爪未达标 | 检查 `controller.limit_barrier_control.gripper.gripper_setpoint`、第八项容差及电流限制 |
| 大臂反馈过期 | 检查驱动、通信、时间戳及 `runtime.state_timeout` |

积分力矩上限为 `ki × i_max`；误差超过 `i_thresh` 时该轴积分清零。容差以实际 YAML 为准；放宽容差只改变通过标准。
