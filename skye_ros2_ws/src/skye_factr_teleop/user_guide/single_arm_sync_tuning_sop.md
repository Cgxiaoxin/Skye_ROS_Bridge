# 单臂同步阶段人机协同调参 SOP

整理日期：2026-10-29。适用对象：现场操作者与协助分析、修改配置的助手。

本文依据仓库中 2026-10-21～26 的走位、保持及真实大臂反馈同步记录，沉淀双方已经使用过的协作方法。历史数值用于解释调参判断；每次试验以实际加载的配置、运行代码和本轮数据为准。

## 1. 目标与适用范围

目标是让小臂从已确认安全的起点，平顺运动到指定目标，完成实测收敛并保持；通过记录定位问题，每轮小步调整，最终形成可重复的参数与证据。

本文中的“小臂”为主端 leader，“大臂”为从端 follower。单臂表示一次只调左侧或右侧。

| 场景 | 目标来源 | 操作入口 | 通过后能说明什么 |
|---|---|---|---|
| 无大臂走位与保持 | 人工指定七轴逻辑角度，另加配置中的夹爪目标 | `skye_factr_sync_trial move` | 共用轨迹、收敛和保持控制在已测条件下可用 |
| 真实大臂反馈同步 | IDLE 时截取本侧新鲜的大臂七轴位置，另加夹爪目标 | `/mode/switch_sync` | 已测主从姿态下的正式同步可用 |

正式同步截取一次目标，大臂在本轮保持静止，并持续提供有效反馈。无大臂走位成功后，仍须单独验证真实反馈同步。本 SOP 到同步、保持和停止为止；`SYNCED → TELEOP` 的切换与遥操按后续阶段单独验收。

## 2. 双方分工与每轮协作闭环

| 现场操作者 | 助手 |
|---|---|
| 确认实体侧别、姿态、线缆、可达性和支撑条件 | 核对配置、坐标、接口与试验条件 |
| 执行启动、记录、运动、停止与回读 | 提供本轮明确命令、文件名、观察点与停止条件 |
| 报告抖动、停顿、补动、碰触、报警和操作时机 | 分析汇总、逐帧 trace 与驱动日志，提出可验证的解释 |
| 决定现场是否继续，异常时立即处置 | 给出最小改动、预期变化与回退方法，整理结论 |

每轮按以下顺序闭环：

1. **明确本轮问题。** 例如“J3 在保持阶段静差超限”，同时写明目标、起点类别和当前配置版本。
2. **固定比较条件。** 尽量复现起点、目标、负载和无接触区间；记录无法保持一致的条件。
3. **准备一份明确的配置。** 优先只改一个轴的一类参数。确需同时改多个量时，列出原因，并限制因果结论。
4. **先启动记录，再发运动请求。** 操作者观察实体，助手依据完整数据分析。
5. **停止、保存、回读。** 对本轮标明正常完成、人工中止、自动超时或硬件故障。
6. **先解释本轮，再安排下一轮。** 输出“事实—判断—改动—验证点—回退条件”，避免边运行边连续换参数。
7. **成功后重复与回归。** 先复现同条件，再覆盖不同起点和常用非零目标，决定保留或回退。

助手给出的配置应标记为“待试验”；只有实测后才能标记为“保留”。操作者已接受的平顺性与耗时可以作为本批次停止优化的依据，剩余性能问题记录为待办。

## 3. 试验前准备

### 3.1 统一环境与配置

所有终端都执行以下公共设置。这里使用当前仓库路径；历史清单中的 `leader_for_skye` 路径不直接照抄。

```bash
cd /home/lyy/projects/skye_ros_bridge/skye_ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=73
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
SIDE=left
CONFIG="$PWD/src/skye_factr_teleop/config/grav_comp_m6_${SIDE}.yaml"
RUN_ID="${SIDE}_sync_20261029_001"
```

`RUN_ID` 每轮更换；日期仅为示例。若试验使用独立 YAML，各终端的 `CONFIG` 均指向该文件的绝对路径。历史现场使用 domain 73 隔离其他主机、容器中的采集及对齐节点；换环境时也须保证所有相关终端使用同一 domain。

源码或构建相关文件变化后，先构建成功，再重新加载安装环境：

```bash
colcon build --packages-up-to skye_factr_teleop --symlink-install
source install/setup.bash
```

**节点和记录器必须使用同一份配置。** YAML 在节点启动时加载，改文件不代表运行中的控制器已更新。每次改参后先停止运动、退出旧节点、重新启动，再创建新记录。不要在运行期间修改同路径 YAML，以免记录器快照与节点实际参数不一致。

### 3.2 核对实体与目标

- 只启动目标侧小臂节点；停止旧控制器、`skye_follower_align` 及其他可能发送运动命令的程序。
- 核对 USB by-id、实体侧别与 YAML 的 `dynamixel_port`，不用 `ttyUSB0/1` 编号判断左右。设备 A 左侧为 `FTBEO9L1`，右侧为 `FTBEO8WL`。
- 串口无其他进程占用；FTDI `latency_timer` 设置为 `1` 并回读。拔插或重启后重新检查。具体命令见[正式同步清单第 2 节](../dev_docs/checklist/phase7_3_follower_sync_checklist.md#2-公共环境与启动)。
- 核对零位、方向、单位与关节顺序。七轴为 `l_j1..l_j7` 或 `r_j1..r_j7`；位置为 rad，速度为 rad/s。
- 当前反馈角度直接用于同步目标；不要额外套用大臂 relative 指令的符号映射，也不要用 `joint_signs` 替代主从语义标定。
- 目标和路径须经实体确认。优先让首轮小臂起点靠近目标；夹爪是第八轴，也会参与运动与收敛。
- 按 `limit_min + safety_margin` 到 `limit_max - safety_margin` 核对目标安全区，并确认路径、线缆和夹爪无干涉。

历史例子：J7 限位为 `[-0.8, 0.8] rad`、安全余量为 `0.1 rad` 时，安全区为 `[-0.7, 0.7] rad`。大臂目标 `0.773859 rad` 虽未超配置限位，已进入屏障介入区，可能与跟踪力矩对抗。此时先核对机械行程、映射和目标需求，再决定配置；不要直接提高增益或扩大限位。

操作者准备好支撑与停止入口。出现明显抖动、异常加速、机械干涉或报警时立即停止，现场处置优先于保存标记。

## 4. 标准操作顺序与终端分配

| 终端 | 用途 |
|---|---|
| A | 大臂驱动，正式同步时使用 |
| B | 本侧小臂节点，保留驱动日志 |
| C | 专门记录，一轮一份文件 |
| D | 反馈检查、运动请求和停止，始终可操作 |
| E（可选） | 独立状态监控 |

### 4.1 启动与检查

正式同步时，终端 A 启动大臂驱动；已有同一驱动运行则沿用。该启动会连接真机并进入控制模式，须先完成现场准备。

```bash
ros2 launch skye_robot_driver skye_robot_driver.launch.py robot_profile:=thor
```

终端 B 启动本侧小臂，显式指定配置并打开逐周期诊断：

```bash
ros2 launch skye_factr_teleop "start_teleop_m6_${SIDE}.launch.py" \
  "${SIDE}_config:=$CONFIG" sync_diagnostics:=true
```

启动后小臂应为 IDLE、扭矩关闭。正式同步前，终端 D 查看大臂反馈：

```bash
ros2 topic echo --once "/gento/${SIDE}_joint_states" sensor_msgs/msg/JointState
```

核对七轴名称、角度、静止状态和时间戳；默认反馈新鲜度门限为 `0.25 s`。单次 echo 只用于采样检查，同步和保持期间仍须持续有效反馈。

### 4.2 先记录

终端 C 执行，等待出现 `Recording ...; awaiting move, then IDLE`：

```bash
ros2 run skye_factr_teleop skye_factr_sync_trial record \
  --side "$SIDE" --config "$CONFIG" --operator lyy \
  --output "/tmp/${RUN_ID}.json" --duration 180
```

输出包括 `.json` 汇总及同名 `.trace.jsonl` 逐帧数据。文件不可覆盖，每轮使用新名称。

**记录器计时结束或 Ctrl+C 只保存记录，不停止小臂。不要把 stop 命令排在阻塞的记录命令后面。** 历史中曾怀疑 stop 延迟，后续操作者补充可能是记录占用终端、stop 尚未执行，因此采用独立停止终端；该现象未被确认为控制器 stop 缺陷。

终端 E 可监控：

```bash
ros2 topic echo /teleop/state std_msgs/msg/String --qos-durability transient_local
```

模式话题是全局入口，因此本流程只运行一侧小臂。

### 4.3 发出本轮请求

**正式大臂反馈同步：** 确认记录已开始、大臂静止、小臂为 IDLE 后，在终端 D 执行：

```bash
ros2 topic pub --once /mode/switch_sync std_msgs/msg/String '{data: switch_sync}'
```

**无大臂走位：** 使用 `move`，先预览，再执行。例如近起点 J1 增加 `0.05 rad`：

```bash
ros2 run skye_factr_teleop skye_factr_sync_trial move \
  --side "$SIDE" --config "$CONFIG" --joint-id 1 --delta 0.05
```

```bash
ros2 run skye_factr_teleop skye_factr_sync_trial move \
  --side "$SIDE" --config "$CONFIG" --joint-id 1 --delta 0.05 --execute
```

相对目标在执行时重新采样，可能与预览略有不同；预览只做数值和轨迹检查，实体路径由操作者确认。归零可改用 `--target 0 0 0 0 0 0 0`，夹爪仍使用配置目标。此入口无需再发 `switch_sync`，也不授予大臂遥操权限。

### 4.4 观察状态并停止

正常序列为 `IDLE → TELEOP_SYNCING → HOLD_SETTLING → SYNCED`：

- `TELEOP_SYNCING`：正在跟随 Ruckig 参考轨迹。
- `HOLD_SETTLING`：参考轨迹结束，等待八轴实测位置和速度连续达标。
- `SYNCED`：已连续满足配置条件，控制器继续保持目标。

`publishing #1` 只证明请求已发布；Ruckig 完成也只证明参考轨迹结束。以控制器状态与 `sync_status` 判断同步结果，不从终端打印次数或丢帧数据推断连续达标。

进入 SYNCED 后观察本轮约定的保持区间，再在终端 D 停止；异常时立即停止：

```bash
ros2 topic pub --once /mode/switch_stop std_msgs/msg/String '{data: switch_stop}'
```

操作者准备扶持前记录人工介入时刻；异常时无需等标记。人工碰触后的数据单独标注，不用于证明无接触保持稳定。新目标须先 stop 回到 IDLE，重复同步请求不会替换当前目标或重启计时。

### 4.5 保存与独立失能回读

确认 IDLE、记录保存后，正常退出终端 B，待串口释放。操作者继续支撑小臂，保持供电、不重启总线，再回读：

```bash
ros2 run skye_factr_teleop skye_factr_dynamixel_readonly_check -- \
  --side "$SIDE" --config "$CONFIG" --frames 2 --interval 0 \
  --output "/tmp/${RUN_ID}_torque_disable.json"
```

检查 `automated_result=PASS`、ID1～8 的 `torque_enabled=false` 及具体检查项。软件缓存失能不能代替寄存器回读；该工具未记录的故障寄存器也不能由 PASS 推断为零。

发生硬件 Alert 时，保存驱动终端日志和实际故障码，先排查硬件、负载与故障状态，再安排下一轮。不要把重启后无故障回读当作历史原因已经消除的证据。

## 5. 助手分析数据的固定顺序

1. **先确认记录可比较。** 核对侧别、配置快照、代码变化、实际八轴起点、最终目标、人工介入和中止原因；检查 `missing_samples`、`sequence_restarts`。同目标但不同起点不能直接作单参数对照。
2. **还原状态与时长。** 分开统计轨迹、收敛和 SYNCED 保持。同步总耗时使用首次 TELEOP_SYNCING 到首次 SYNCED 的单调时间差，包含连续达标时间；CLI 启动和连接等待另算。
3. **定位未达标轴。** 分别检查位置误差、速度、连续达标计时。区分人工 stop、`sync_timeout`、`settle_timeout`、反馈过期和硬件报警。
4. **先看电流和周期。** 比较 `current_before_clip_ma`、`current_after_clip_ma`、`present_current_ma`，统计逐轴限幅阶段与占比；检查 `cycle_dt_s` 与 500 Hz 名义周期 `0.002 s` 的差异。
5. **再拆力矩来源。** 分别看 tracking、gravity、friction、limit、nullspace，判断补偿不足、跟踪请求不足、屏障对抗或输出受限。
6. **检查切换与保持。** 观察轨迹到保持时的误差、电流、停顿和补动，以及 SYNCED 后是否再次漂移或抖动。
7. **核对停止证据与范围。** 同步试验中 `follower_command_count` 应为 0；软件零输出、缓存失能和独立硬件回读分别描述。

数据解释约定：

| 数据 | 解读方式 |
|---|---|
| `target_position_rad` | 轨迹阶段是本周期参考；评估最终收敛时使用最终保持目标 |
| `*_torque_nm` | 计算出的逻辑指令力矩分项，不能当作实测关节力矩 |
| `current_before_clip_ma / current_after_clip_ma` | 按物理 ID1～8 排列；裁剪后仍可能有寄存器量化 |
| `present_current_ma` | 本周期写入前读取，不能要求与同帧新命令完全一致 |
| `transitions` | 有诊断丢帧时，不能当作控制器相邻周期的电流差 |
| `RECORDED / INCOMPLETE` | 记录完成状态，实机验收仍需结合现场、运动数据与硬件回读 |

## 6. 调参决策表：先找限制，再改参数

| 现象与证据 | 下一步 | 历史经验 |
|---|---|---|
| 误差较大，裁剪前请求持续超过上限 | 先确认可达性、无干涉、周期及控制分项；确需电流余量时做逐步试验 | 提高上限只解除限制，不会自动增加请求，也不能替代控制调参 |
| 静差持续，但命令未裁剪 | 查看保持 P/I、积分是否到顶或被清零、重力残差和静摩擦 | J7 取消限幅后仍有静差，继续抬电流上限缺少直接依据 |
| 保持积分达到上限 | 按 `ki × i_max` 计算积分力矩上限，再判断是否小步调整 | J3/J7 曾受积分力矩上限限制；仅看 `i_max` 数字无法比较输出能力 |
| 误差在 `i_thresh` 外 | 检查是否因积分被清零而停在远端；结合可达性与输出预算评估阈值 | J3 曾因误差超过 `0.15 rad` 而不能持续积累积分 |
| 速度超差、零位附近抖动，D 项较大 | 检查速度反馈、延迟、周期和 D 项请求，必要时回退近期增加的 Kd | 早期增大 J3/J5 保持 Kd 后明显抖动，回退到 `0.05` 后三轮成功；因两轴同时回退，未唯一确定根因 |
| 大偏差起点轨迹抖动 | 单独检查轨迹 PD 与实际速度，不沿用近起点通过结论 | 正式同步中曾降低 J3 轨迹 Kd 改善后续表现，但原大偏差起点仍需同条件回归 |
| 轨迹结束后停顿，再缓慢补动 | 对照终点误差、两阶段控制输出与补偿项，判断交接变化和剩余静差 | 已加入 `0.5 s` 平滑交接；实测减轻突变后仍可能需要较长收敛 |
| 目标进入限位屏障区 | 先核对目标需求、机械行程、标定和安全区 | J7 典型目标曾与屏障区冲突，增加增益可能加剧力矩对抗 |
| 最后一帧达标但未进入 SYNCED | 检查八轴速度与连续达标时长 | 瞬时达标不等于完成 `settle_duration` |

保持积分含义必须区分清楚：`I += error × dt`，仅在 `abs(error) <= i_thresh` 时积累，否则该轴清零；`I` 被限制在 `±i_max`，单位为 rad·s；积分力矩为 `ki × I`。`i_thresh` 决定积分介入范围，`sync_position_tolerance` 决定到位判定，两者用途不同。

实施改参时遵守以下顺序：

1. 先排除目标、映射、限位、外力、硬件和数据问题。
2. 分开分析轨迹 PD 与保持 PID；确认是哪一阶段、哪一轴受限。
3. 每轮优先只改一个轴的一类参数，明确旧值、新值、预期与回退条件。
4. 改完复测本阶段及相邻切换；增加积分后还要检查越零、超调与长时间保持。
5. 单独记录容差、超时或速度上限的变化。放宽验收门限会改变通过定义，不能记成控制精度提高。

Ruckig 的速度、加速度和 jerk 限制约束参考轨迹；实测运动受闭环、负载和限幅影响。提高 Kd 也不必然增加稳定性。历史中仅 D 项的估算电流就曾超过该轴电流上限，不能把速度超差统一归因于阻尼不足。

当前轨迹到保持交接使用 `w = 3x² - 2x³`，在 `0.5 s` 内混合实时终点 PD 与保持 PID，两阶段重力增益同样交接；诊断字段为 `sync_status.hold_blend_weight`。这是代码中的固定时长，不是现有 YAML 参数。它减小控制切换的突变，不能保证消除静摩擦或补偿残差造成的停顿。

## 7. 成功后的回归与收尾

- 同条件重复，确认成功不是一次偶然；再覆盖零位、常用非零位和代表性的不同起点。
- 对曾失败的大偏差起点单独回归；未复测前不外推成功范围。
- 每轮既检查能否进入 SYNCED，也检查整段平顺性、实际速度、限幅、切换和保持。
- 人工接触后的末段单独标注；批次末回读只证明该次回读结果，不写成每轮均独立验证。
- 运动中 stop、受控超时、反馈中断分别记录。异常路径采用明确、受控方式，不通过卡住机构制造超时。
- 左右侧独立验证；更换零点、设备、负载或控制版本后重新界定适用范围。
- 将保留参数、配置差异、成功范围和剩余问题写入结论；接受当前效果后结束本批次调参。
